# Note classification vs agent category

_Generated by `classify`; do not edit by hand._

## Summary

- **Our topic and the agent's label disagree on 6,210 of 42,751 tickets (14.5%)** at subcategory level (6,210 at category level).
- **6,210 of those are one pattern:** a specific complaint filed as *Others › Unclassified*. 6,210 of the 6,892 Unclassified tickets (90.1%) describe a concrete problem — no signal, a package charged but not activated, and so on.
- Disagreements of any other kind: **0**. When an agent picks a specific category, it matches the note.
- The habit is uniform (≈15% across every channel, region, priority and topic — see below), so agent-labelled volumes **miss about 15% of every real topic** (our counts are ~18% higher) while keeping the shape of its trend. *Others* looks "large" mostly because of it.
- The local model (`qwen2.5:7b`) agreed with the human review on **88 of 91** distinct texts (97.0% of tickets); on the 89 texts with one clear topic, **86 of 89**. Final topics use the review.
- **2 texts (964 tickets) fit more than one topic.** They are listed apart in section 1b, a person decides each, and every text that needs a person is queued in `output/needs_human_check.csv`.

The spread is narrow everywhere, so this looks like a uniform labelling habit — Unclassified used as a default when the agent is unsure or rushed — rather than one team. The data has no agent ID, so it cannot be traced further.

## 5. Limitations

- One note per ticket, one topic per note. A note mentioning two problems gets the dominant one.
- The review is one person's judgment. A second reviewer and an agreement score (Cohen's κ) would be the next step before using this for agent coaching.
- With 91 distinct texts every label can be reviewed. Real notes are mostly unique; see the README for how this would change at scale.
